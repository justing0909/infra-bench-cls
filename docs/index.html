These tiers refer to GPU memory (VRAM) rather than system RAM. Fine-tuning has to hold the whole backbone and its gradients in VRAM, so it needs far more than a linear probe does. The peak VRAM beside each recommendation is measured from our own runs, not estimated.

Not sure what you have? Check your GPU on Windows ↗ · Check your graphics card on a Mac ↗

With no dedicated GPU, pick No GPU. A linear probe still works, since you can extract the frozen features once on CPU and then train a small head on top. Apple-silicon machines share a single pool of memory between CPU and GPU, so treat your total RAM as the ceiling.

A label pairs a place with a class, so you know the location holds a wastewater plant and it is tagged as one. Here each label is a single satellite tile of a single asset, which means a few hundred labels is a few hundred tiles you have already identified.

What matters is the count, not the file format. In practice they arrive as:

  • CSV or Parquet — asset id, class, coordinates
  • GeoJSON or Shapefile — point or polygon locations
  • GeoTIFF — the imagery tiles themselves

With none at all, these results cannot help you directly, because every condition here is supervised. Label a modest set first and use the 0.3× column as a guide to what it buys you, or else look to zero-shot methods, which this benchmark does not cover.

Not sure keeps both data scales in the running and returns whichever scores highest, so you can see the ceiling without committing to a label budget yet.

For scale, 1.0× is our full training split and 0.3× a 30% subsample of it, and both are scored on the same —-tile test set. Below roughly a hundred examples for a class, expect that class to land under what the table shows.

3 · What are you classifying?

The small figures are counts, showing test tiles per seed beside a class and member classes beside a sector. Rarer classes have fewer tiles to go on, so their scores move around more between seeds.

Pick any combination of classes you like. With none picked, the ranking uses the whole-set metric below, and with some picked it becomes the average of just those classes' F1 scores. Either way, the table further down follows the same selection.

The sector button on each row toggles that whole row at once, and picking a sector in full gives you exactly the per-sector F1 from the paper, which is defined the same way: the macro average of its member classes, with each one scored on the full test set.

Only F1 exists per class in the stored results, so the metric selector works on the whole set, meaning none picked or all ten, and locks on anything in between.
