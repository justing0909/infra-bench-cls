Infra-Bench CLS

Notes

What the benchmark measures, how the numbers are computed, and where to be careful reading them.

Results Figures Notes Cite GitHub ↗

The task

Single-label classification of critical-infrastructure assets from satellite imagery. Asset locations come from OpenStreetMap across seven continental regions, and each one is imaged with co-located Sentinel-2 L2A optical and Sentinel-1 SAR tiles at 10 m resolution. Every model is evaluated on the same fixed spatial split, so train and test assets never share a spatial block.

Models differ in which bands they take and in how they fuse SAR with optical, so each evaluation notebook records its own band mapping.

Conditions

Each model runs under up to four conditions, pairing two adaptation protocols with two data scales.

LP
Linear probe. The backbone is frozen and only a linear head is trained.
FT
Fine-tune. The full backbone is trained with layer-wise learning-rate decay.
Sup
Supervised. The ResNet-18 baseline, trained end to end from scratch.
1.0× / 0.3×
The full training set and a 30% subsample of it, which together give the label-efficiency comparison.

Two models are linear-probe only. AlphaEarth is an embedding product rather than an image backbone, so there is nothing to fine-tune, and Random Features is a ResNet-18 frozen at initialization, included as a floor. Every condition runs at three seeds (314, 271, 161), and all figures are the mean with population standard deviation across them.

Why ten classes?

The full ontology has thirteen classes, three of which are dropped here. Wind farm and port terminal have only three test tiles each per seed, which is too few for a stable per-class F1.

Water works is dropped for a different reason. It is hard to tell apart from wastewater plants and storage tanks, both in the imagery and in how OpenStreetMap tags it. That makes the label itself unreliable, so a model can identify a site correctly and still be scored wrong.

That leaves ten classes carrying 2,689 of the original 2,813 test tiles per seed. Macro and weighted F1, accuracy, precision and recall are all recomputed on the subset, though per-class F1 needs no adjustment, because a class's F1 does not depend on which others are averaged with it.

Reading the metrics

Scores are shown as percentages, but an F1 of 57.9% does not mean right 57.9% of the time. F1 is the harmonic mean of two separate rates. Recall is the share of real sites a model finds, while precision is how often it is right when it chooses a class. Pick a single class in the recommender and you will see both rates on their own.

Macro F1
Per-class F1 averaged with equal weight, so rare classes count as much as common ones. The headline metric.
Weighted F1
Per-class F1 weighted by test support, so it tracks the common classes.
Per-sector F1
The macro average of per-class F1s for that sector's retained classes, each scored on the full test set rather than on a sector-filtered subset, since filtering first would hide false positives and inflate the score. Telecom has only one class, so its column is just that class's F1.
Recall
Uses each class's true support as the denominator.
Precision
Counts only predictions landing in the ten retained classes.
GMACs
One forward pass at batch 16. Values marked * come from an architecture-matched stand-in, used where the original loader was unavailable, which is fair because GMACs depends on architecture rather than on trained weights. AlphaEarth reports zero, since it has no backbone forward pass to count.

Caveats

Per-region F1 is on the thirteen-class basis. The stored results record it already averaged over classes, so it cannot be recomputed on the ten-class subset. Compare models against each other within that breakdown, but not against numbers elsewhere on the site.

The results hold no per-region, per-class figure at all, so nothing here can answer which model is best at airports in Asia. The recommender therefore ranks on your class selection and reports the regional picture alongside it instead.

Tile extraction may undercount slightly in some regions. We chose not to re-extract globally, since the effect on F1 is small next to the differences between models, and the repository README documents the specifics.
